# Flash Attention 知识点

> 本文档详细介绍 Flash Attention 系列算法的原理、实现和优化技术。

---

## 1. 概述

### 1.1 背景与动机

注意力机制是 Transformer 架构的核心，但存在两个主要瓶颈：

| 问题 | 标准注意力 | 影响 |
|:-----|:-----------|:-----|
| **内存复杂度** | O(N²) | 长序列时 GPU 内存不足 |
| **IO 瓶颈** | 频繁 HBM 访问 | GPU 计算单元利用率低 |

**Flash Attention 的解决方案**：
- 分块计算 (Tiling)：将 O(N²) 内存降至 O(N)
- IO 感知 (IO-Aware)：最小化 HBM 访问，最大化 SRAM 利用

### 1.2 版本演进

```
Flash Attention V1 (2022)
├── 分块计算 + 重计算
├── 内存: O(N²) → O(N)
└── 性能: 2-4x speedup

Flash Attention V2 (2023)
├── 优化并行策略
├── 减少非 GEMM 操作
└── 性能: 2x over V1

Flash Attention V3 (2024)
├── Warp-Specialization
├── GEMM-Softmax 重叠
├── FP8 低精度
└── 性能: 1.5-2x over V2, 740 TFLOPs/s
```

## 2. 理论基础

### 2.1 标准注意力计算

给定 Query (Q), Key (K), Value (V) ∈ ℝ^(N×d)：

```
S = Q @ K^T / √d        # 注意力分数 [N, N]
P = softmax(S)          # 注意力权重 [N, N]
O = P @ V               # 输出 [N, d]
```

**问题**：需要存储 S 和 P，内存 O(N²)

### 2.2 在线 Softmax 算法

Flash Attention 的核心是**在线 Softmax**，无需预先知道全局 max：

```python
# 初始化
m = -∞      # 当前最大值
l = 0       # 指数和
o = 0       # 输出累积

# 对每个块 j
for j in range(num_blocks):
    S_j = Q @ K_j^T / √d
    
    # 更新最大值
    m_new = max(m, rowmax(S_j))
    
    # 缩放因子
    scale_old = exp(m - m_new)
    scale_new = exp(S_j - m_new)
    
    # 更新累积
    l = l * scale_old + rowsum(scale_new)
    o = o * scale_old + scale_new @ V_j
    
    m = m_new

# 最终归一化
O = o / l
```

**数学证明**：

设 x = [x₁, x₂, ..., xₙ]，标准 softmax：
```
softmax(x)ᵢ = exp(xᵢ) / Σⱼ exp(xⱼ)
            = exp(xᵢ - m) / Σⱼ exp(xⱼ - m)  # 数值稳定
```

分块计算时，设 x = [x_A, x_B]：
```
m = max(max(x_A), max(x_B))
l = Σ exp(x_A - m) + Σ exp(x_B - m)
softmax(x) = [exp(x_A - m) / l, exp(x_B - m) / l]
```

### 2.3 IO 复杂度分析

设 M = SRAM 大小，N = 序列长度，d = 头维度

| 算法 | HBM 访问次数 |
|:-----|:-------------|
| 标准注意力 | O(N·d + N²) |
| Flash Attention | O(N²·d / M) |

当 M >> d 时，Flash Attention 显著减少 IO。

## 3. Flash Attention V1/V2

### 3.1 V1 核心算法

```
Algorithm: FlashAttention Forward Pass
Input: Q, K, V ∈ ℝ^(N×d), block sizes Br, Bc
Output: O ∈ ℝ^(N×d)

1. 将 Q 分成 Tr = ⌈N/Br⌉ 块
2. 将 K, V 分成 Tc = ⌈N/Bc⌉ 块
3. 初始化 O = 0, l = 0, m = -∞

4. for i = 1 to Tr:
5.     加载 Qᵢ 到 SRAM
6.     for j = 1 to Tc:
7.         加载 Kⱼ, Vⱼ 到 SRAM
8.         计算 Sᵢⱼ = Qᵢ @ Kⱼ^T
9.         更新 m, l, O (在线 softmax)
10.    写回 Oᵢ 到 HBM

Memory: O(N) - 只存储 O, l, m
```

### 3.2 V2 优化

V2 的关键改进：

1. **循环顺序优化**：外层遍历 Q 块，内层遍历 KV 块
2. **减少 rescaling**：延迟归一化到最后
3. **更好的并行**：在序列维度上并行

```python
# V1: 内层循环 Q
for j in kv_blocks:
    for i in q_blocks:
        ...

# V2: 内层循环 KV (更好的数据局部性)
for i in q_blocks:
    for j in kv_blocks:
        ...
```

## 4. Flash Attention V3

### 4.1 Warp-Specialization

V3 将 warp 分为 Producer 和 Consumer：

```
┌─────────────────────────────────────────────────────────┐
│  Producer Warp (TMA)          Consumer Warp (Tensor Core)│
│  ┌─────────────────┐          ┌─────────────────────┐   │
│  │ 从 HBM 加载     │ ──────→  │ GEMM (WGMMA)        │   │
│  │ K_j, V_j        │          │ Softmax             │   │
│  │ 到 SMEM         │          │ 累积输出            │   │
│  └─────────────────┘          └─────────────────────┘   │
│         ↑                              ↓                │
│         └──── Circular SMEM Buffer ────┘                │
└─────────────────────────────────────────────────────────┘
```

**优势**：
- 数据加载与计算并行
- 减少 warp 间同步
- 更好的指令调度

### 4.2 Pingpong 调度

2-stage 流水线实现 GEMM-Softmax 重叠：

```
时间 →
Stage 0: GEMM(S₀) ────────────────────────────
Stage 1:          Softmax(S₀) + GEMM(S₁) ─────
Stage 0:                       Softmax(S₁) + GEMM(S₂)
...
```

**关键洞察**：
- GEMM 是计算密集型 (Tensor Core)
- Softmax 是内存密集型 (CUDA Core)
- 两者可以并行执行

### 4.3 FP8 低精度

#### 4.3.1 FP8 格式

| 格式 | 指数位 | 尾数位 | 范围 | 用途 |
|:-----|:-------|:-------|:-----|:-----|
| E4M3 | 4 | 3 | ±448 | 前向传播 |
| E5M2 | 5 | 2 | ±57344 | 梯度 |

#### 4.3.2 Block Quantization

将张量分成小块，每块独立量化：

```python
def block_quantize(x, block_size=256):
    blocks = x.reshape(-1, block_size)
    scales = blocks.abs().max(dim=1) / FP8_MAX
    x_quantized = (blocks / scales).round().clamp(-FP8_MAX, FP8_MAX)
    return x_quantized, scales
```

**优势**：每块有独立的缩放因子，减少量化误差

#### 4.3.3 Incoherent Processing

对抗 outlier 的技术：

```python
# 1. 生成随机正交矩阵 R (Hadamard)
R = hadamard_matrix(d) / sqrt(d)

# 2. 量化前变换
x_transformed = x @ R

# 3. 量化
x_quantized = quantize_fp8(x_transformed)

# 4. 反变换
x_output = x_quantized @ R.T
```

**原理**：正交变换将 outlier 的影响分散到多个元素

## 5. 性能分析

### 5.1 理论性能

H100 GPU 规格：
- FP16 Tensor Core: 989 TFLOPs/s
- FP8 Tensor Core: 1978 TFLOPs/s
- HBM 带宽: 3.35 TB/s

Flash Attention V3 实测：
- FP16: 740 TFLOPs/s (75% 利用率)
- FP8: 1.2 PFLOPs/s (60% 利用率)

### 5.2 FLOPs 计算

注意力的 FLOPs：
```
QK^T:    2 × B × H × N × N × d
Softmax: 5 × B × H × N × N
PV:      2 × B × H × N × N × d
Total:   (4d + 5) × B × H × N²
```

因果掩码减少约 50% 计算。

### 5.3 内存占用

| 组件 | 标准注意力 | Flash Attention |
|:-----|:-----------|:----------------|
| Q, K, V | 3Nd | 3Nd |
| S = QK^T | N² | Br × Bc |
| P = softmax(S) | N² | Br × Bc |
| O | Nd | Nd |
| **总计** | O(N² + Nd) | O(Nd) |

## 6. 实现细节

### 6.1 块大小选择

最优块大小取决于：
- SRAM 容量 (H100: 228KB/SM)
- 头维度 d
- 数据类型

经验值：
- d=64: Br=Bc=128
- d=128: Br=Bc=64
- d=256: Br=Bc=32

### 6.2 因果掩码优化

因果掩码 (Causal Mask) 使得 query[i] 只能看到 key[j] where j ≤ i：

```python
# 跳过完全被掩码的块
if kv_block_start > q_block_end:
    continue  # 整个块被掩码

# 部分掩码的块
causal_mask = k_indices <= q_indices
scores = where(causal_mask, scores, -inf)
```

### 6.3 数值稳定性

关键技巧：
1. 减去 rowmax 防止 exp 溢出
2. 使用 FP32 累积器
3. 最后才做归一化

## 7. 使用示例

```python

# 创建 Flash Attention V3
```
