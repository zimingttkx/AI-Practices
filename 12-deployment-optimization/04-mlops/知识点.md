## 1. MLOps 概述

### 1.1 定义

**MLOps** = Machine Learning + Operations（机器学习运维）

**核心目标**: 让模型从"实验室能跑"变成"生产环境稳定运行"

```
┌─────────────────────────────────────────────────────────────┐
│                    传统ML vs MLOps                          │
├─────────────────────────────────────────────────────────────┤
│  传统ML:  训练 → 导出模型 → 手动部署 → 祈祷不出问题        │
│  MLOps:   训练 → 自动测试 → 自动部署 → 自动监控 → 自动修复 │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 核心组件

| 组件 | 作用 | 类比 |
|:-----|:-----|:-----|
| 实验追踪 | 记录每次训练的配置和结果 | 实验室笔记本 |
| 模型注册 | 管理模型版本和上线流程 | 软件版本库 |
| 生产监控 | 实时监控模型表现 | 汽车仪表盘 |
| 漂移检测 | 发现数据分布变化 | 质量检测仪 |
| 自动重训练 | 模型效果下降时自动更新 | 自动维修系统 |

### 1.3 成熟度级别

```
Level 0: 手动流程
├── 手动训练、手动部署、手动监控
└── 问题: 效率低、易出错、难复现

Level 1: ML流水线
├── 自动化训练流程
└── 问题: 部署仍需手动

Level 2: CI/CD流水线
├── 自动化训练 + 自动化部署
└── 问题: 无法自动应对线上问题

Level 3: 完全自动化 (目标)
├── 自动训练 + 自动部署 + 自动监控 + 自动重训练
└── 人类只需设计和审核
```

## 2. 实验追踪

### 2.1 定义

**实验追踪**: 系统性记录每次模型训练的所有信息，包括参数、指标、模型文件、代码版本。

**解决的问题**:
- "上周那个效果好的模型用的什么参数？" → 有记录
- "这次训练为什么比上次差？" → 可对比
- "能复现三个月前的实验吗？" → 能复现

### 2.2 核心概念

```
┌─────────────────────────────────────────────────────────────┐
│                    实验追踪数据结构                          │
├─────────────────────────────────────────────────────────────┤
│  Experiment (实验)                                          │
│  └── Run (运行) ← 一次完整的训练过程                        │
│      ├── Parameters (参数) ← 训练前设置的配置               │
│      │   例: learning_rate=0.001, batch_size=32            │
│      ├── Metrics (指标) ← 训练过程中产生的数值              │
│      │   例: loss=0.5, accuracy=0.95                       │
│      ├── Artifacts (产物) ← 训练产生的文件                  │
│      │   例: model.pt, config.yaml                         │
│      └── Tags (标签) ← 用于分类和搜索                       │
│          例: env=production, team=cv                       │
└─────────────────────────────────────────────────────────────┘
```

**关键区分**:
- **参数(Parameters)**: 训练**前**设置，不会变化（如学习率）
- **指标(Metrics)**: 训练**中**产生，随时间变化（如损失值）

### 2.3 实现原理

```python
# 实验追踪器的核心数据结构
from dataclasses import dataclass, field
from typing import Dict, List, Any
import time
import json
from pathlib import Path

@dataclass
class Experiment:
    """
    实验记录类

    设计思路:
    - 使用dataclass自动生成__init__等方法
    - params存储训练前的配置
    - metrics存储训练中的指标（按名称分组，每个指标是一个列表）
    """
    name: str                                          # 实验名称
    params: Dict[str, Any] = field(default_factory=dict)  # 超参数
    metrics: Dict[str, List[float]] = field(default_factory=dict)  # 指标历史
    artifacts: List[str] = field(default_factory=list)    # 产物文件路径
    start_time: float = field(default_factory=time.time)  # 开始时间

class ExperimentTracker:
    """
    实验追踪器

    核心功能:
    1. log_params(): 记录超参数（训练前调用一次）
    2. log_metrics(): 记录指标（训练中多次调用）
    3. log_artifact(): 记录文件（训练后调用）
    """

    def __init__(self, experiment_name: str, save_dir: str = "./experiments"):
        self.experiment = Experiment(name=experiment_name)
        self.save_dir = Path(save_dir) / experiment_name
        self.save_dir.mkdir(parents=True, exist_ok=True)  # 创建保存目录

    def log_params(self, params: Dict[str, Any]):
        """
        记录超参数

        为什么用update而不是赋值？
        → 允许分多次记录，后面的会覆盖前面的同名参数
        """
        self.experiment.params.update(params)

    def log_metrics(self, metrics: Dict[str, float], step: int = None):
        """
        记录指标

        为什么metrics是Dict[str, List]而不是Dict[str, float]？
        → 同一个指标会记录多次（每个epoch一次），需要保存历史

        参数:
            metrics: {"loss": 0.5, "accuracy": 0.95}
            step: 当前步数（可选，用于绘图时的x轴）
        """
        for key, value in metrics.items():
            if key not in self.experiment.metrics:
                self.experiment.metrics[key] = []  # 首次记录，创建空列表
            self.experiment.metrics[key].append(value)  # 追加到历史

    def log_artifact(self, file_path: str):
        """记录产物文件路径"""
        self.experiment.artifacts.append(file_path)

    def save(self):
        """
        保存实验记录到JSON文件

        为什么用JSON？
        → 人类可读、跨语言、易于版本控制
        """
        with open(self.save_dir / "experiment.json", "w") as f:
            json.dump({
                "name": self.experiment.name,
                "params": self.experiment.params,
                "metrics": self.experiment.metrics,
                "artifacts": self.experiment.artifacts,
                "start_time": self.experiment.start_time,
                "end_time": time.time()
            }, f, indent=2)
```

### 2.4 使用示例

```python
# 完整的训练+追踪流程
tracker = ExperimentTracker("resnet50_cifar10")

# 1. 记录超参数（训练前）
tracker.log_params({
    "model": "resnet50",
    "learning_rate": 0.001,
    "batch_size": 32,
    "epochs": 100,
    "optimizer": "adam"
})

# 2. 训练循环中记录指标
for epoch in range(100):
    train_loss = train_one_epoch(model, train_loader)
    val_acc = evaluate(model, val_loader)

    # 每个epoch记录一次
    tracker.log_metrics({
        "train_loss": train_loss,
        "val_accuracy": val_acc
    }, step=epoch)

    # 保存最佳模型
    if val_acc > best_acc:
        torch.save(model.state_dict(), "best_model.pt")
        tracker.log_artifact("best_model.pt")

# 3. 保存实验记录
tracker.save()
```

## 3. 模型注册

### 3.1 定义

**模型注册中心**: 集中管理模型版本、元数据和生命周期的系统。

**解决的问题**:
- "线上跑的是哪个版本的模型？" → 有记录
- "新模型有问题，能回滚吗？" → 能回滚
- "这个模型是谁训练的？用什么数据？" → 有追溯

### 3.2 核心概念

```
┌─────────────────────────────────────────────────────────────┐
│                    模型注册中心结构                          │
├─────────────────────────────────────────────────────────────┤
│  RegisteredModel (注册模型)                                 │
│  └── 名称: image_classifier                                 │
│      ├── Version 1.0 (Archived)    ← 已归档，不再使用       │
│      │   └── accuracy=0.92                                  │
│      ├── Version 2.0 (Production)  ← 生产环境正在使用       │
│      │   └── accuracy=0.95                                  │
│      └── Version 3.0 (Staging)     ← 预发布，测试中         │
│          └── accuracy=0.96                                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 模型生命周期

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ Development │ →  │   Staging   │ →  │ Production  │ →  │  Archived   │
│   (开发)    │    │  (预发布)   │    │   (生产)    │    │  (归档)     │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
      │                  │                  │                  │
      ▼                  ▼                  ▼                  ▼
   单元测试          集成测试           A/B测试            保留备份
   代码审查          性能测试           全量上线           可回滚
```

**阶段说明**:
- **Development**: 开发中，可能不稳定
- **Staging**: 预发布，在测试环境验证
- **Production**: 生产环境，服务真实用户
- **Archived**: 已归档，保留用于回滚

### 3.4 实现原理

```python
from enum import Enum
from dataclasses import dataclass
from typing import Dict, Optional
import shutil
from pathlib import Path
import time

class ModelStage(Enum):
    """
    模型阶段枚举

    为什么用Enum而不是字符串？
    → 防止拼写错误，IDE自动补全，类型安全
    """
    DEVELOPMENT = "development"
    STAGING = "staging"
    PRODUCTION = "production"
    ARCHIVED = "archived"

@dataclass
class ModelVersion:
    """
    模型版本信息

    包含模型的所有元数据，用于追溯和审计
    """
    version: str              # 版本号，如 "1.0.0"
    stage: ModelStage         # 当前阶段
    model_path: str           # 模型文件路径
    metrics: Dict[str, float] # 性能指标
    created_at: float         # 创建时间戳
    description: str = ""     # 版本描述

class ModelRegistry:
    """
    模型注册中心

    核心功能:
    1. register_model(): 注册新版本
    2. transition_stage(): 转换阶段
    3. get_model(): 获取指定版本/阶段的模型
    """

    def __init__(self, registry_path: str = "./model_registry"):
        self.registry_path = Path(registry_path)
        self.registry_path.mkdir(parents=True, exist_ok=True)
        self.models: Dict[str, Dict[str, ModelVersion]] = {}  # {模型名: {版本: 信息}}

    def register_model(
        self,
        name: str,
        model_path: str,
        version: str,
        metrics: Dict[str, float] = None
    ) -> ModelVersion:
        """
        注册模型

        流程:
        1. 创建版本目录
        2. 复制模型文件到注册中心
        3. 记录元数据
        """
        # 创建目录: registry/模型名/版本号/
        model_dir = self.registry_path / name / version
        model_dir.mkdir(parents=True, exist_ok=True)

        # 复制模型文件（保证注册中心有独立副本）
        dest_path = model_dir / Path(model_path).name
        shutil.copy(model_path, dest_path)

        # 创建版本记录
        model_version = ModelVersion(
            version=version,
            stage=ModelStage.DEVELOPMENT,  # 新注册的模型默认在开发阶段
            model_path=str(dest_path),
            metrics=metrics or {},
            created_at=time.time()
        )

        # 保存到内存索引
        if name not in self.models:
            self.models[name] = {}
        self.models[name][version] = model_version

        return model_version

    def transition_stage(self, name: str, version: str, stage: ModelStage):
        """
        转换模型阶段

        重要规则: 同一模型只能有一个Production版本
        → 推送新版本到Production时，旧版本自动归档
        """
        if name in self.models and version in self.models[name]:
            # 如果推送到Production，先归档旧的Production版本
            if stage == ModelStage.PRODUCTION:
                for v in self.models[name].values():
                    if v.stage == ModelStage.PRODUCTION:
                        v.stage = ModelStage.ARCHIVED

            self.models[name][version].stage = stage

    def get_model(
        self,
        name: str,
        version: str = None,
        stage: ModelStage = None
    ) -> Optional[ModelVersion]:
        """
        获取模型

        两种获取方式:
        1. 按版本号: get_model("classifier", version="1.0")
        2. 按阶段: get_model("classifier", stage=ModelStage.PRODUCTION)
        """
        if name not in self.models:
            return None

        if stage:
            # 按阶段查找
            for v in self.models[name].values():
                if v.stage == stage:
                    return v
        elif version:
            # 按版本查找
            return self.models[name].get(version)
        else:
            # 返回最新版本
            versions = sorted(self.models[name].keys())
            return self.models[name][versions[-1]] if versions else None

        return None
```

### 3.5 版本号规范

推荐使用**语义化版本号** (Semantic Versioning):

```
主版本.次版本.修订号
  │       │      │
  │       │      └── 修复bug，不影响功能
  │       └────────── 新增功能，向后兼容
  └────────────────── 重大变更，不向后兼容

示例:
1.0.0 → 1.0.1  # 修复bug
1.0.1 → 1.1.0  # 新增功能
1.1.0 → 2.0.0  # 架构重构
```

## 4. 生产监控

### 4.1 定义

**生产监控**: 实时收集和分析模型在生产环境中的表现数据。

**解决的问题**:
- "模型上线后效果怎么样？" → 有数据
- "响应时间是否正常？" → 有监控
- "什么时候需要重训练？" → 有告警

### 4.2 监控指标分类

```
┌─────────────────────────────────────────────────────────────┐
│                     监控指标分类                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  系统指标              模型指标              业务指标        │
│  (基础设施)           (模型表现)            (业务价值)       │
│  ──────────           ──────────            ──────────      │
│  CPU使用率            预测延迟              转化率          │
│  内存使用率           吞吐量(QPS)           点击率          │
│  GPU利用率            错误率                收入            │
│  网络带宽             准确率                用户满意度      │
│                       数据漂移                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**指标优先级**:
1. **错误率**: 最重要，直接影响用户体验
2. **延迟**: 影响用户等待时间
3. **准确率**: 影响业务效果
4. **资源使用**: 影响成本

### 4.3 延迟指标详解

```
延迟百分位数 (Percentile):
┌─────────────────────────────────────────────────────────────┐
│  P50 (中位数): 50%的请求在此时间内完成                       │
│  P90: 90%的请求在此时间内完成                                │
│  P99: 99%的请求在此时间内完成 ← 最常用的SLA指标             │
│  P99.9: 99.9%的请求在此时间内完成                            │
└─────────────────────────────────────────────────────────────┘

为什么用P99而不是平均值？
→ 平均值会被极端值拉高/拉低，无法反映大多数用户体验
→ P99能保证99%的用户体验在可接受范围内

示例:
  请求延迟: [10, 12, 11, 13, 500] ms
  平均值: 109.2 ms  ← 被500拉高，不能反映真实情况
  P50: 12 ms       ← 大多数请求的真实延迟
```

### 4.4 实现原理

```python
from collections import deque
from typing import Dict, List, Optional
import statistics
import time

class MetricsMonitor:
    """
    指标监控器

    核心功能:
    1. record_latency(): 记录延迟
    2. record_prediction(): 记录预测结果
    3. get_stats(): 获取统计信息
    4. check_alerts(): 检查告警
    """

    def __init__(self, window_size: int = 10000):
        """
        参数:
            window_size: 滑动窗口大小，只保留最近N条记录
                        → 避免内存无限增长
                        → 反映最近的系统状态
        """
        self.window_size = window_size
        self._latencies = deque(maxlen=window_size)  # 延迟记录
        self._predictions = deque(maxlen=window_size)  # 预测记录
        self._labels = deque(maxlen=window_size)  # 真实标签
        self._total_requests = 0
        self._failed_requests = 0

    def record_latency(self, latency_ms: float):
        """记录一次请求的延迟"""
        self._latencies.append(latency_ms)
        self._total_requests += 1

    def record_prediction(self, prediction, label=None, latency_ms: float = None):
        """
        记录一次预测

        参数:
            prediction: 模型预测结果
            label: 真实标签（如果有延迟反馈）
            latency_ms: 推理延迟
        """
        self._predictions.append(prediction)
        if label is not None:
            self._labels.append(label)
        if latency_ms is not None:
            self.record_latency(latency_ms)

    def record_error(self, error_msg: str = None):
        """记录一次错误"""
        self._total_requests += 1
        self._failed_requests += 1

    def get_stats(self) -> Dict:
        """
        获取统计信息

        返回:
            - 请求统计: 总数、成功数、失败数、错误率
            - 延迟统计: 平均、P50、P90、P99
            - 准确率: 如果有标签数据
        """
        stats = {
            "total_requests": self._total_requests,
            "successful_requests": self._total_requests - self._failed_requests,
            "failed_requests": self._failed_requests,
            "error_rate": self._failed_requests / self._total_requests if self._total_requests > 0 else 0
        }

        # 延迟统计
        if self._latencies:
            latencies = list(self._latencies)
            stats["latency_avg"] = statistics.mean(latencies)
            stats["latency_p50"] = statistics.median(latencies)
            stats["latency_p90"] = self._percentile(latencies, 90)
            stats["latency_p99"] = self._percentile(latencies, 99)

        # 准确率（如果有标签）
        if self._labels and len(self._labels) == len(self._predictions):
            correct = sum(1 for p, l in zip(self._predictions, self._labels) if p == l)
            stats["accuracy"] = correct / len(self._labels)

        return stats

    def _percentile(self, data: List[float], p: int) -> float:
        """计算百分位数"""
        sorted_data = sorted(data)
        index = int(len(sorted_data) * p / 100)
        return sorted_data[min(index, len(sorted_data) - 1)]
```

## 5. 数据漂移检测

### 5.1 定义

**数据漂移 (Data Drift)**: 生产环境中的数据分布与训练数据分布发生变化。

**为什么重要**: 模型是基于训练数据学习的，如果线上数据分布变了，模型效果必然下降。

### 5.2 漂移类型

```
┌─────────────────────────────────────────────────────────────┐
│                     漂移类型分类                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  数据漂移 (Covariate Shift)                                 │
│  - P(X) 发生变化                                            │
│  - 输入特征的分布改变                                        │
│  - 例: 用户年龄分布从25-35变成18-25                         │
│                                                             │
│  概念漂移 (Concept Drift)                                   │
│  - P(Y|X) 发生变化                                          │
│  - 特征与标签的关系改变                                      │
│  - 例: 疫情期间，同样的用户行为对应不同的购买意图            │
│                                                             │
│  标签漂移 (Label Drift)                                     │
│  - P(Y) 发生变化                                            │
│  - 标签的分布改变                                            │
│  - 例: 欺诈率从1%上升到5%                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 检测方法

#### KS检验 (Kolmogorov-Smirnov Test)

**原理**: 比较两个分布的累积分布函数(CDF)的最大差异

```python
from scipy import stats
import numpy as np

def ks_test(reference: np.ndarray, current: np.ndarray, threshold: float = 0.05):
    """
    KS检验

    原理:
    1. 计算两个样本的累积分布函数(CDF)
    2. 找到两个CDF之间的最大垂直距离
    3. 如果距离大于临界值，认为分布不同

    参数:
        reference: 参考数据（训练集）
        current: 当前数据（线上数据）
        threshold: p值阈值，小于此值认为有漂移

    返回:
        drift_detected: 是否检测到漂移
        p_value: p值，越小越可能有漂移
    """
    statistic, p_value = stats.ks_2samp(reference, current)

    return {
        "drift_detected": p_value < threshold,
        "statistic": statistic,  # KS统计量，范围[0,1]，越大差异越大
        "p_value": p_value       # p值，越小越可能有漂移
    }

# 示例
reference = np.random.normal(50, 10, 1000)  # 训练数据：均值50，标准差10
current_similar = np.random.normal(50, 10, 500)  # 相似数据
current_drifted = np.random.normal(70, 10, 500)  # 漂移数据：均值变成70

print(ks_test(reference, current_similar))  # drift_detected: False
print(ks_test(reference, current_drifted))  # drift_detected: True
```

#### PSI (Population Stability Index)

**原理**: 比较两个分布在各个区间的占比差异

```python
def calculate_psi(reference: np.ndarray, current: np.ndarray, bins: int = 10):
    """
    PSI计算

    原理:
    1. 将数据分成N个区间（bins）
    2. 计算每个区间在两个分布中的占比
    3. PSI = Σ (actual% - expected%) × ln(actual% / expected%)

    PSI解读:
    - < 0.1: 无显著变化
    - 0.1 ~ 0.2: 轻微变化，需关注
    - > 0.2: 显著变化，需要行动
    """
    # 计算分位数边界（基于参考数据）
    breakpoints = np.percentile(reference, np.linspace(0, 100, bins + 1))

    # 计算每个区间的占比
    ref_counts = np.histogram(reference, bins=breakpoints)[0]
    cur_counts = np.histogram(current, bins=breakpoints)[0]

    ref_pct = ref_counts / len(reference) + 1e-6  # 加小值避免除零
    cur_pct = cur_counts / len(current) + 1e-6

    # 计算PSI
    psi = np.sum((cur_pct - ref_pct) * np.log(cur_pct / ref_pct))

    return {
        "psi": psi,
        "drift_detected": psi > 0.2,
        "severity": "none" if psi < 0.1 else ("minor" if psi < 0.2 else "major")
    }
```

### 5.4 检测策略

| 策略 | 适用场景 | 优点 | 缺点 |
|:-----|:---------|:-----|:-----|
| 定时检测 | 数据量大、变化慢 | 资源消耗低 | 可能延迟发现 |
| 实时检测 | 数据量小、变化快 | 及时发现 | 资源消耗高 |
| 滑动窗口 | 平衡方案 | 兼顾及时性和资源 | 需要调参 |

## 6. 自动重训练

### 6.1 定义

**自动重训练**: 当检测到模型效果下降或数据漂移时，自动触发模型重新训练。

### 6.2 触发策略

```
┌─────────────────────────────────────────────────────────────┐
│                    重训练触发策略                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  定时触发 (Scheduled)                                       │
│  - 每周/每月固定重训练                                       │
│  - 适合: 数据稳定增长的场景                                  │
│                                                             │
│  漂移触发 (Drift-based)                                     │
│  - 检测到数据漂移时触发                                      │
│  - 适合: 数据分布可能突变的场景                              │
│                                                             │
│  性能触发 (Performance-based)                               │
│  - 模型指标下降超过阈值时触发                                │
│  - 适合: 有实时反馈的场景                                    │
│                                                             │
│  混合触发 (Hybrid)                                          │
│  - 结合多种策略                                              │
│  - 适合: 生产环境                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 6.3 实现示例

```python
from enum import Enum
from dataclasses import dataclass
from typing import Callable
import time

class RetrainTrigger(Enum):
    SCHEDULED = "scheduled"      # 定时
    DRIFT = "drift"              # 漂移
    PERFORMANCE = "performance"  # 性能

@dataclass
class RetrainConfig:
    """重训练配置"""
    trigger: RetrainTrigger
    schedule_interval: int = 86400 * 7  # 默认每周（秒）
    drift_threshold: float = 0.2        # PSI阈值
    performance_threshold: float = 0.05 # 性能下降阈值
    min_samples: int = 1000             # 最小样本数

class AutoRetrainer:
    """
    自动重训练管理器

    核心逻辑:
    1. 根据配置的触发策略检查是否需要重训练
    2. 满足条件时执行训练函数
    3. 更新基线指标
    """

    def __init__(self, config: RetrainConfig, train_fn: Callable, evaluate_fn: Callable):
        self.config = config
        self.train_fn = train_fn      # 训练函数
        self.evaluate_fn = evaluate_fn # 评估函数
        self.last_retrain_time = time.time()
        self.baseline_performance = None
        self.samples_since_retrain = 0

    def check_and_retrain(self, drift_score: float, current_performance: float) -> bool:
        """
        检查是否需要重训练

        返回: 是否触发了重训练
        """
        should_retrain = False
        reason = None

        # 定时检查
        if self.config.trigger == RetrainTrigger.SCHEDULED:
            if time.time() - self.last_retrain_time > self.config.schedule_interval:
                should_retrain = True
                reason = "scheduled"

        # 漂移检查
        elif self.config.trigger == RetrainTrigger.DRIFT:
            if drift_score > self.config.drift_threshold:
                should_retrain = True
                reason = f"drift_score={drift_score:.3f}"

        # 性能检查
        elif self.config.trigger == RetrainTrigger.PERFORMANCE:
            if self.baseline_performance:
                perf_drop = self.baseline_performance - current_performance
                if perf_drop > self.config.performance_threshold:
                    should_retrain = True
                    reason = f"performance_drop={perf_drop:.3f}"

        # 执行重训练
        if should_retrain and self.samples_since_retrain >= self.config.min_samples:
            print(f"触发重训练: {reason}")
            new_model = self.train_fn()
            self.baseline_performance = self.evaluate_fn(new_model)
            self.last_retrain_time = time.time()
            self.samples_since_retrain = 0
            return True

        return False
```

## 7. A/B测试

### 7.1 定义

**A/B测试**: 将用户随机分成两组，分别使用不同版本的模型，通过统计方法比较效果差异。

**为什么需要**: 离线指标好不代表线上效果好，需要在真实环境中验证。

### 7.2 核心概念

```
┌─────────────────────────────────────────────────────────────┐
│                    A/B测试流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户请求 → 流量分配 → 模型预测 → 记录结果 → 统计分析       │
│               │                                             │
│        ┌──────┴──────┐                                      │
│        ▼             ▼                                      │
│    控制组(A)     实验组(B)                                   │
│    旧模型        新模型                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**关键术语**:
- **控制组 (Control)**: 使用现有模型的用户组
- **实验组 (Treatment)**: 使用新模型的用户组
- **统计显著性**: 结果差异不是随机波动的概率

### 7.3 流量分配

```python
import hashlib

def get_variant(user_id: str, experiment_id: str, control_ratio: float = 0.5) -> str:
    """
    一致性哈希分配

    为什么用哈希而不是随机数？
    → 同一用户每次访问都分到同一组，保证体验一致性
    → 不需要存储用户分组信息

    参数:
        user_id: 用户ID
        experiment_id: 实验ID
        control_ratio: 控制组比例

    返回:
        "control" 或 "treatment"
    """
    # 将用户ID和实验ID组合后哈希
    hash_input = f"{experiment_id}:{user_id}"
    hash_value = int(hashlib.md5(hash_input.encode()).hexdigest(), 16)

    # 取模得到0-999的数字
    bucket = hash_value % 1000

    # 根据比例分配
    if bucket < control_ratio * 1000:
        return "control"
    else:
        return "treatment"
```

### 7.4 统计显著性检验

```python
import numpy as np
from scipy import stats

def ab_test_significance(
    control_conversions: int,
    control_total: int,
    treatment_conversions: int,
    treatment_total: int,
    alpha: float = 0.05
) -> dict:
    """
    A/B测试显著性检验（双比例z检验）

    参数:
        control_conversions: 控制组转化数
        control_total: 控制组总数
        treatment_conversions: 实验组转化数
        treatment_total: 实验组总数
        alpha: 显著性水平（通常0.05）

    返回:
        is_significant: 是否显著
        p_value: p值
        lift: 提升幅度
    """
    # 计算转化率
    p1 = control_conversions / control_total
    p2 = treatment_conversions / treatment_total

    # 合并转化率
    p_pool = (control_conversions + treatment_conversions) / (control_total + treatment_total)

    # 标准误
    se = np.sqrt(p_pool * (1 - p_pool) * (1/control_total + 1/treatment_total))

    # z统计量
    z = (p2 - p1) / se if se > 0 else 0

    # p值（双尾检验）
    p_value = 2 * (1 - stats.norm.cdf(abs(z)))

    return {
        "control_rate": p1,
        "treatment_rate": p2,
        "lift": (p2 - p1) / p1 if p1 > 0 else 0,  # 相对提升
        "p_value": p_value,
        "is_significant": p_value < alpha,
        "recommendation": "采用新模型" if (p_value < alpha and p2 > p1) else "保持现状"
    }

# 示例
result = ab_test_significance(
    control_conversions=500, control_total=10000,   # 控制组: 5%转化率
    treatment_conversions=550, treatment_total=10000 # 实验组: 5.5%转化率
)
print(f"提升: {result['lift']:.1%}")
print(f"显著性: {result['is_significant']}")
print(f"建议: {result['recommendation']}")
```

## 8. 特征存储

### 8.1 定义

**特征存储 (Feature Store)**: 集中管理和服务机器学习特征的系统。

**解决的问题**:
- 训练和推理使用不同的特征计算逻辑 → 统一管理
- 重复计算相同特征 → 复用
- 特征定义不一致 → 标准化

### 8.2 核心概念

```
┌─────────────────────────────────────────────────────────────┐
│                    特征存储架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  离线存储 (Offline Store)                                   │
│  - 存储历史特征数据                                          │
│  - 用于模型训练                                              │
│  - 高吞吐量，延迟不敏感                                      │
│                                                             │
│  在线存储 (Online Store)                                    │
│  - 存储最新特征值                                            │
│  - 用于实时推理                                              │
│  - 低延迟，高可用                                            │
│                                                             │
│  特征注册 (Feature Registry)                                │
│  - 特征元数据管理                                            │
│  - 特征版本控制                                              │
│  - 特征血缘追踪                                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 8.3 实现示例

```python
from dataclasses import dataclass
from typing import Dict, List, Any
import time

@dataclass
class Feature:
    """特征定义"""
    name: str           # 特征名称
    dtype: str          # 数据类型
    description: str    # 描述
    entity: str         # 实体类型（如user, item）
    online: bool = True # 是否支持在线获取
    ttl_seconds: int = 86400  # 过期时间

class FeatureStore:
    """
    特征存储

    核心功能:
    1. register_feature(): 注册特征定义
    2. ingest(): 写入特征值
    3. get_online_features(): 在线获取（低延迟）
    4. get_historical_features(): 离线获取（批量）
    """

    def __init__(self):
        self.features: Dict[str, Feature] = {}
        self.online_store: Dict[str, Dict] = {}   # entity_id -> {feature: value}
        self.offline_store: List[Dict] = []       # 历史记录

    def register_feature(self, feature: Feature):
        """注册特征"""
        self.features[feature.name] = feature

    def ingest(self, entity_id: str, features: Dict[str, Any], timestamp: float = None):
        """
        写入特征值

        同时写入在线和离线存储
        """
        timestamp = timestamp or time.time()

        # 写入在线存储（覆盖旧值）
        if entity_id not in self.online_store:
            self.online_store[entity_id] = {}
        self.online_store[entity_id].update(features)
        self.online_store[entity_id]['_timestamp'] = timestamp

        # 写入离线存储（追加）
        record = {'entity_id': entity_id, 'timestamp': timestamp, **features}
        self.offline_store.append(record)

    def get_online_features(self, entity_id: str, feature_names: List[str]) -> Dict:
        """
        在线获取特征

        用于实时推理，要求低延迟
        """
        if entity_id not in self.online_store:
            return None
        return {k: self.online_store[entity_id].get(k) for k in feature_names}

    def get_historical_features(
        self,
        entity_ids: List[str],
        feature_names: List[str],
        start_time: float = None,
        end_time: float = None
    ) -> List[Dict]:
        """
        离线获取历史特征

        用于模型训练，支持时间范围过滤
        """
        results = []
        for record in self.offline_store:
            if record['entity_id'] not in entity_ids:
                continue
            if start_time and record['timestamp'] < start_time:
                continue
            if end_time and record['timestamp'] > end_time:
                continue
            results.append({k: record.get(k) for k in ['entity_id', 'timestamp'] + feature_names})
        return results
```
